What This Page Does

Benchmark scores need translation.

Model launch posts collapse a lot of nuance into a few bold numbers. This page is meant to slow that down. It covers the benchmark itself, the shape of the questions, who made it, when it appeared, whether the data is public, how the scoring works, and what a strong result probably means in practice.

Use it like this

Start with the capability family, then check whether the benchmark is public, dynamic, or guarded. After that, ask whether the metric is objective, execution-based, or judge-based.

Public MCQ is easy to compare

It is also the easiest to saturate, memorize, and overfit.

LLM-judge evals are useful

They are fast and practical, but judge bias and style bias are real.

Fresh or private tests matter

As models get stronger, contamination resistance becomes part of the benchmark quality story.

Score Reading

How to read a benchmark result

Different metrics reward different behavior. A high pass@k, a high judge win rate, and a high factual accuracy score are not interchangeable.

Accuracy / Exact Match

Best when there is one correct answer and a deterministic grader. Common in MCQ, short-answer QA, and math.

pass@k

Mostly used in coding. It tells you whether one of several tries succeeds, which can hide instability compared with pass@1.

Win Rate / Judge Score

Useful for assistant quality and open-ended prompts. Also sensitive to verbosity, style, and the judge model itself.

Resolved Rate / Attack Success

Common in SWE and safety. These feel closer to deployment because the system must actually fix or resist something.

MCQ inflation

Multiple choice can reward elimination strategies and memorized answer patterns without proving deep reasoning.

Contamination

Old public datasets leak into pretraining corpora, prompt collections, and evaluation harnesses. Freshness matters.

Context mirage

A model can advertise a 128K or 1M window and still fail once the task moves beyond simple retrieval.

Coverage

Capability families worth checking

A decent capability snapshot usually spans more than one family. The interesting question is how the model profile changes across them.

Knowledge / Exams

MMLU, GPQA, ARC, AGIEval, C-Eval, CMMLU. Breadth, science depth, and academic exam performance.

Math

GSM8K, MATH, FrontierMath. Arithmetic is not the same thing as frontier mathematical reasoning.

Code / SWE

HumanEval, MBPP, DS-1000, SWE-bench, LiveCodeBench. Code snippets and repo-scale software engineering are very different tasks.

Chat / Instruction

IFEval, MT-Bench, AlpacaEval, Arena-Hard-Auto. Great for assistant quality and format following, but often judge-based.

Truth / Safety

TruthfulQA, SimpleQA, HaluEval, HarmBench. Factuality, hallucination, and robust refusal each probe a different failure mode.

Long Context

LongEval, LongBench, L-Eval, InfiniteBench, RULER. These test whether long windows are genuinely usable.

Chinese / Bilingual

C-Eval, CMMLU, GAOKAO-Bench, AGIEval, LongBench, InfiniteBench. Localization changes both knowledge coverage and phrasing.

Agent / Frontier

LiveBench, BrowseComp, Humanity's Last Exam. These try to stay useful after older public suites get saturated.
